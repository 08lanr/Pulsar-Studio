# Launch and Monitor screen acceptance, 2026-09-16

References inspected: Overlord `StepMassLaunch.tsx` and `MonitorTab.tsx`; Grow `MassLaunch.tsx` and `LaunchMonitor.tsx`; Studio's approved `docs/unified-launch.md` and `docs/launch-review-response.md`. This is a functional parity check for the new Studio screens. Overlord's operator-only card, Everflow, warm-up, shell and Smart+ flows are outside Studio's approved flow.

| Area | Reference behavior | Studio acceptance |
| --- | --- | --- |
| Platform and accounts | Pick a platform/account set, search usage, filter and rescan; never treat unread usage as free | TikTok and Meta provider switch; assigned accounts only; usage scan, search, chips, quick pick and rescan. Select all and quick picks operate on the visible filtered set. |
| Content allocation | Separate codes per campaign by default, or reuse one set; preview exact distribution | TikTok accepts manually pasted Spark codes in Launch. Meta accepts existing Facebook/Instagram post IDs and finished Studio video. Unique/shared allocation and exact item count are validated by the plan. |
| Campaign settings | Campaign count, ad count, destination, daily pacing, cost cap, start state and preset are reviewable | Plan shows account, campaign, content and each row's allocated lifetime budget. The entered lifetime budget is total across the run; per-row allocation is the immutable maximum for in-place controls. |
| Approval | Preview before a provider write; explicit paused/live state | Save, preview and approver-only submit remain separate. Staff launch requires an on-behalf note. The 15% service fee is outside provider media spend. |
| Monitor states | On/Off switch separate from review and effective delivery; reason and freshness available | Configured On/Off uses the provider's observed configured status. Missing status reads “Switch unknown,” never guessed from the launch default. Delivery/review is a separate line with notes and last check time. |
| Monitor measurements | Spend, clicks, CPC, conversions, review breakdown; missing values stay unavailable | Run and row metrics display unavailable values as dashes. CTR and cost per conversion require observed numerator and denominator; no synthetic zero. Ad status and notes appear in row details. |
| Controls | Switch, budget/cost cap, schedule, group controls, duplicate and end as permitted | Completed, non-ended campaigns expose applicable controls. Daily pacing control appears only when the row has daily pacing; TikTok-only group and duplicate controls stay TikTok-only. End remains available during incomplete preparation. Budget prompt states the signed row ceiling and New round path. |
| New round | Copy choices into a fresh approval | New round creates a draft and requires another preview/approval, including a higher budget. |

The fixture browser test now covers two TikTok accounts, four campaigns and eight unique Sparks; configured Off then On with review/delivery states; budget reduction/restoration within the original row ceiling; and a paused Meta launch with an existing post plus a finished-video upload. A separate four-campaign case covers a $500 total approval with $20 daily pacing per campaign, a cost-cap preset, budget/daily/bid controls, ending one campaign, staff seeing the same rows, and a freshly approved $600 round 2 with new provider campaign IDs.

The final uninterrupted full browser run passed all 30 cases, including all six launch cases across desktop and presentation viewports. The delayed-response new-round test reproduces the former draft-loading race and verifies the editor waits for saved values before accepting edits. TypeScript, lint and the production build passed. Production provider eligibility and official Meta MCP OAuth remain separate live checks; database status is documented in [production readiness](production-launch-readiness-2026-09-16.md).
