# Segment a film in Studio

Decision 2026-09-23 (top of `docs/decisions.md`), plan `connection-segment-plan.md` part B. Studio drives the canonical cut-only scripts of `mini-drama-system/drama-remix` as background jobs inside a film folder it created; the run row is `studio.film_runs` (migration 0016, `docs/data-model.md` §9); the worker is `scripts/segment-worker.ts`. The sections before "Screens" are the worker's and its routes' (task 2c).

## How it works

A **run** (`studio.film_runs`) is one film going through the cut-only route: a source file picked on the server, a film folder `<WORKSPACE_ROOT>/<bucket>/<slug>` Studio creates (or adopts, when the same source is already in place), the pipeline's own scripts synced into `cut/scripts/` and run there, and the phase-1 import at the end. The row is the progress record: `stage`, `stage_detail` (what the stage found or is doing), `decisions` (every human decision, who and when), `error_text` (a script's refusal, verbatim), the drama-remix commit the scripts came from, a lease and a CAS `revision`. Nothing lives only in process memory, so a worker restart resumes from the row plus the artifacts on disk.

**The worker** (`lib/segment/worker.ts`) ticks every few seconds: it lists the runs, claims each actionable one (a CAS on the revision plus a ten-minute lease), and drives it stage by stage until it waits for a person, ends, or fails. While a script runs, every thirty seconds the lease is renewed, the `segment_film` job row is heartbeated, and the row is re-read: a cancel from the desk aborts the child (`taskkill /T /F`) and releases the locks. A waiting run holds no lease, so any worker may pick it up once a decision arrives.

- **Supabase mode:** the separate process `npx tsx scripts/segment-worker.ts` (launch config `studio-segment-worker`; `--once` runs one tick). It reads `.env.local` like the dev server. A stage can run for an hour and a dev-server restart would kill its children, which is why it is not inside Next.
- **Fixture mode:** the fixture store is the dev server's own memory, so a second process would see no runs; the same loop runs inside the dev server (`ensureInProcessWorker`, booted by the first call to a runs route; `STUDIO_SEGMENT_WORKER=off` keeps it off). A dev-server restart is a worker restart: the run resumes from its artifacts.
- **The fake pipeline** (`STUDIO_FAKE_PIPELINE=1`, `lib/segment/fake-runner.ts`): every cut-only script stood in by plausible artifacts derived from `tests/fixtures/workspace/low-quality/fixture-film` (a 15 s film with a 4–6 s band), so the e2e server and `tests/segment-worker.test.ts` walk every stage without Python, ffmpeg or a model key. Its film folders live under `<STUDIO_WORK_DIR>/fake-workspace/<bucket>/<slug>`, never in the checked-in fixture tree; the hand-off imports from that root. The fake keeps the two rules the review depends on (apply_vision.py's rules via `applyVision`, `--verify`'s strip checks) and judges from a table: the first boundary sure, the second below the gate with a skeptic override.

**The stage machine** (`lib/segment/stages.ts` is the vocabulary; one module per stage). Each stage answers `next` (move on), `wait` (a person, or a readiness poll) or `fail` (the refusal, verbatim, on `error_text`; `stage_detail.failed_stage` says where). A waiting stage records `stage_detail.waiting = {for, since, retry_after?}` and `stage_detail.decisions_seen`; decisions after that count are pending, and a stage that acts on one and moves on marks them consumed (`consumed()`), so a join recorded at film-meta is still there when the render runs. Resume is per artifact: every stage skips what it finds finished (a transcript, a strips file, the pass file, a plan already carrying the choices).

`stage_detail` keys the screens read: `progress` (`{step, t, of}` for a render, `{step, file, line}` for the index log, `{step, judged, of}` for the pass), `source` (the probe), `scripts` (sha, dirty), `watermark` (box, images), `index` (counts), `options`, `review` (needs / decided / pre-accepted / missing / out-of-band), `render`, `qa`, `film_meta`, `import`, `handoff` (the command), `waiting_for_heavy_lock` (who holds the machine's slot), `apply_faults`, `band`, `unavailable`, `failed_stage`, `rejudges_done`.

**Locks.** `cut/.studio-run.json` is taken when a run is first driven (adopted by the same run on a restart; a live foreign one fails the run with its holder named) and removed when the run ends; it stays while the run waits for a person, so a session sees Studio owns the folder. The machine's `.heavy-lock.json` (`HEAVY_LOCK_ROOT`, else above `WORKSPACE_ROOT`; the work dir under the fake) is taken around the index, the render and the QA, and carries the run's `run_id`: one worker process drives several runs at once, so the same pid is not the same holder — a second run waits for the first, and a release removes only the lock its own run wrote; when a session or another run holds it live, the run waits, renewing its lease and showing the holder in `waiting_for_heavy_lock`. A stale lock (dead pid, or older than six hours) is replaced and the replacement logged.

**Snapshots and Studio's own files.** Before every apply and every render, `cut/review/*` (without the frame strips and QA sheets) and `cut/cuts.json` are copied to `<STUDIO_WORK_DIR>/<run id>/snapshots/<label>-<stamp>/` (`projects/` is not in git). The run's log is `<work>/logs/run.log`; the skeptic's dense strips go to `<work>/dense/`; proxy clips (±5 s, 480 px, made by ffmpeg from the source on first request) to `<work>/proxies/t<s>_<ms>.mp4`; the QA report as it was before an `--only` run to `<work>/qa/`. Nothing of Studio's lands in `projects/` beyond what the pipeline itself writes.

**Refusals shown verbatim.** A script's exit 1 fails the stage with `refusalOf`: the block from the first `REFUSED` / `FAIL` / `NOT READY` line on stdout, else the `sys.exit("…")` text on stderr, prefixed `<script> exited <code>`. Examples the desk shows as written: `pick_cuts.py exited 1 / REFUSED: this film has delivered cuts (review/cuts-0-900-DELIVERED.json). Add --pin-from …`; `cut_episodes.py exited 1 / REFUSED - nothing rendered: / no index/watermark.json - run watermark.py --detect, or pass --no-delogo …`; `boundary_frames.py exited 1 / NOT READY - 3 fault(s) across 12 options: …`; the sync's `drama-remix has uncommitted changes (…): commit them, or allow a dirty tree in the run's settings`. Studio never retries with `--force`, `--no-pin`, `--allow-recut` or `--no-delogo` on its own; `{kind: "retry"}` sends a failed run back to the stage that failed, unchanged.

**Cancel** (`POST …/cancel`) writes `cancelled` at once (the CAS ignores the lease) and removes the run lock; a worker mid-script sees it at its next heartbeat, kills the child and releases the heavy lock. The film folder is left as it is.

**Routes** (staff; the create, decide and cancel routes admin only; same-origin guard, zod, JSON): `GET /api/admin/films/sources?dir=<downloads|onedrive|workspace|extraN|fake|absolute path>&probe=1` (the picker: Downloads, OneDrive "Mini Drama", the workspace, `STUDIO_SOURCE_ROOTS` folders; a typed path must be inside one), `POST /api/admin/films/runs` (one live run per film folder), `GET /api/admin/films/runs[?producer_id]`, `GET /api/admin/films/runs/[runId]` → `{run, stage_view}` (`lib/segment/view.ts`; `lib/segment/api-types.ts` re-exports the types), `POST …/decide`, `POST …/cancel`, `GET /api/film-runs/[runId]/evidence/<review|index|work>/<path>.<png|json|mp4>` (Range honoured; nothing else is served: never an episode, never the source).

**Environment:** `WORKSPACE_ROOT`, `STUDIO_WORK_DIR`, `DRAMA_REMIX_ROOT`, `STUDIO_PIPELINE_PYTHON`, `HEAVY_LOCK_ROOT`, `STUDIO_BASH` (as `.env.example` documents them), plus `STUDIO_FAKE_PIPELINE=1` (the fake), `STUDIO_SOURCE_ROOTS` (extra picker folders, `;`-separated on Windows), `STUDIO_SEGMENT_WORKER=off` (no in-process worker), `STUDIO_FAKE_FIXTURE_FILM` (the film the fake derives from). Tests: `tests/segment-stages.test.ts` (the pure pieces), `tests/segment-worker.test.ts` (the whole run over the fake, cancel, a landscape refusal, a band-breaking move, a join with the QA merge, a re-judge, the hand-off, a resume, a first proof extended under its pins, a delivered film and a session's folder refused without the explicit settings).

## Screens

Staff only (decision 2026-09-23 #9); the sidebar entry "Segment a film" sits beside "Import films". Every screen reads through the staff routes; `lib/segment/api-types.ts` is the one module that holds the wire contract — zod for the request bodies, kept in step with the routes' own parsers, and type re-exports of the served replies (`StageView`, `BoundaryView`, `SourceListing`, `QaReport`, `FilmMetaForm`), so the screens render exactly what `lib/segment/view.ts` builds. Every image or clip URL comes ready-made in the stage view (`strip_url`, `proxy_url`, `image_urls`, `sheets[].url`); a screen never composes an evidence path. Strings live under `seg.*` in `locales/_keys/segment.json`; the classes are in `app/segment.css` (prefix `sgm-`, tokens only; `.seg` is the segmented control and is not ours).

**What the screens derive and what they never do.** `components/admin/segment/model.ts` is the pure model the tests cover (`tests/segment-screens.test.ts`): `buildCards` reads the served `BoundaryView` (status, reasons, applied time, current time) into cards; `episodesOf` / `neighbours` / `checkMove` / `bandConflictGroups` / `applyReady` are the length arithmetic, the same rule the decide route runs (`moveRefusal`), so a refusal is seen before it is sent; `orderCards` is the B3 order; `progressText` puts the worker's `stage_detail` into words. The screens never hand-edit `choices.json`, never compose a pipeline command themselves (the hand-off call comes from the worker), and never retry a refusal on their own: a failed run shows the pipeline's words and Retry goes back to the stage that failed with nothing added.

**e2e** (`tests/e2e/segment.spec.ts`, fixture server with `STUDIO_FAKE_PIPELINE=1`): the desk → New run → the typed path `tests/fixtures/workspace/low-quality/fixture-film/cut/eps` (under the workspace root the picker allows) → `ep01.mp4` (probed 720×1280) → slug `e2e-<stamp>`, first proof off → Start → the watermark step's images and Accept → the review screen lists every option boundary, Accept on each `needs_decision` card, Apply → render → the QA sheets at `film_meta` → the join review lists the pairs with Move enabled → the film-meta form (saving ends the wait) → Import now once the worker waits for the import → the run reads `done` with a `title_id` and "Open the title" lands on the title.
