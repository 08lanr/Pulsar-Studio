# Segment a film in Studio

Decision 2026-09-23 (top of `docs/decisions.md`), plan `connection-segment-plan.md` part B. Studio drives the canonical cut-only scripts of `mini-drama-system/drama-remix` as background jobs inside a film folder it created; the run row is `studio.film_runs` (migration 0016, `docs/data-model.md` §9); the worker is `scripts/segment-worker.ts`. The sections before "Screens" are the worker's and its routes' (task 2c).

## How it works

A **run** (`studio.film_runs`) is one film going through the cut-only route: a source file picked on the server, a film folder `<WORKSPACE_ROOT>/<bucket>/<slug>` Studio creates (or adopts, when the same source is already in place), the pipeline's own scripts synced into `cut/scripts/` and run there, and the phase-1 import at the end. The row is the progress record: `stage`, `stage_detail` (what the stage found or is doing), `decisions` (every human decision, who and when), `error_text` (a script's refusal, verbatim), the drama-remix commit the scripts came from, a lease and a CAS `revision`. Nothing lives only in process memory, so a worker restart resumes from the row plus the artifacts on disk.

**The worker** (`lib/segment/worker.ts`) ticks every few seconds: it lists the runs, claims each actionable one (a CAS on the revision plus a ten-minute lease), and drives it stage by stage until it waits for a person, ends, or fails. While a script runs, every thirty seconds the lease is renewed, the `segment_film` job row is heartbeated, and the row is re-read: a cancel from the desk aborts the child (`taskkill /T /F`), stops an API pass between model calls (the judge and the band fix take the run's signal), and releases the locks. A waiting run holds no lease, so any worker may pick it up once a decision arrives.

- **Supabase mode:** the separate process `npx tsx scripts/segment-worker.ts` (launch config `studio-segment-worker`; `--once` runs one tick). It reads `.env.local` like the dev server. A stage can run for an hour and a dev-server restart would kill its children, which is why it is not inside Next.
- **Fixture mode:** the fixture store is the dev server's own memory, so a second process would see no runs; the same loop runs inside the dev server (`ensureInProcessWorker`, booted by the first call to a runs route; `STUDIO_SEGMENT_WORKER=off` keeps it off). A dev-server restart is a worker restart: the run resumes from its artifacts.
- **The fake pipeline** (`STUDIO_FAKE_PIPELINE=1`, `lib/segment/fake-runner.ts`): every cut-only script stood in by plausible artifacts derived from `tests/fixtures/workspace/low-quality/fixture-film` (a 15 s film with a 4–6 s band), so the e2e server and `tests/segment-worker.test.ts` walk every stage without Python, ffmpeg or a model key. Its film folders live under `<STUDIO_WORK_DIR>/fake-workspace/<bucket>/<slug>`, never in the checked-in fixture tree; the hand-off imports from that root. The fake keeps the two rules the review depends on (apply_vision.py's rules via `applyVision`, `--verify`'s strip checks) and judges from a table: the first boundary sure, the second below the gate with a skeptic override.

**The stage machine** (`lib/segment/stages.ts` is the vocabulary; one module per stage). Each stage answers `next` (move on), `wait` (a person, or a readiness poll) or `fail` (the refusal, verbatim, on `error_text`; `stage_detail.failed_stage` says where). A waiting stage records `stage_detail.waiting = {for, since, retry_after?}` and `stage_detail.decisions_seen`; decisions after that count are pending, and a stage that acts on one and moves on marks them consumed (`consumed()`), so a join recorded at film-meta is still there when the render runs. Resume is per artifact: every stage skips what it finds finished (a transcript, a strips file, the pass file, a plan already carrying the choices).

`stage_detail` keys the screens read: `progress` (`{step, t, of}` for a render, `{step, file, line}` for the index log, `{step, judged, of}` for the pass), `source` (the probe), `scripts` (sha, dirty), `watermark` (box, images), `index` (counts), `options`, `review` (needs / decided / pre-accepted / missing / out-of-band), `render`, `qa`, `film_meta`, `import`, `handoff` (the command), `waiting_for_heavy_lock` (who holds the machine's slot), `apply_faults`, `band`, `unavailable`, `failed_stage`, `rejudges_done`.

**Locks.** `cut/.studio-run.json` is taken once the intake's folder check has passed (a refused folder never gets the file) and before every later stage (adopted by the same run on a restart; a live foreign one fails the run with its holder named), and removed when the run ends; it stays while the run waits for a person, so a session sees Studio owns the folder. The machine's `.heavy-lock.json` (`HEAVY_LOCK_ROOT`, else above `WORKSPACE_ROOT`; the work dir under the fake) is taken around the index, the render and the QA, and carries the run's `run_id`: one worker process drives several runs at once, so the same pid is not the same holder — a second run waits for the first, and a release removes only the lock its own run wrote; when a session or another run holds it live, the run waits, renewing its lease and showing the holder in `waiting_for_heavy_lock`. A stale lock (dead pid, or older than six hours) is replaced and the replacement logged.

**The frame judge, second pass (decision 2026-09-23 "The frame judge, second pass").** The first calibration of the API pass against He Hated All Women's first twenty boundaries scored 4/20; the diagnosis found the recorded Workflow right at 15 of the 16 disagreements, the API skeptic the cause of most misses (nine fixes named, none right, every one applied by `apply_vision.py`'s rule 1), and the reviewer misled by the motion flag, the missing film notes, captions running across the cut and mixed-up tiles. What changed, all in Studio (`lib/segment/vision.ts`, `lib/prompts/boundary-*.ts`, `lib/segment/annotate.ts`; the pipeline repo is untouched):

- **Guarded overrides.** A skeptic's `better_t` is a candidate, not an answer. `guardOverride` applies four checks in order: (a) the time is a tile of an image the skeptic received (an option strip's centre or a dense tile, `SEEN_TOLERANCE_S` 0.05 s); (b) both episodes stay in the band against the planner's neighbours (`neighboursOf`, the fixed start of an extended film from the newest DELIVERED pins); (c) it is not inside or at the start of a card span (`loadCardSpans`: `film-meta.json` exclusions of kind `card`, `index/skips.json`); (d) it is a listed option or a legal cut of the index. A fix that fails is not applied: the record carries the reviewer's pick (`agree: true`) with the skeptic's verdict as `verdict.skeptic_raw` and the refusal as `verdict.guard {outcome: "rejected", rule, detail, better_t}`, and the review shows the boundary as `needs_decision` with reason `skeptic_unverified`. A fix that passes goes to a **blind tie-break** (`lib/prompts/boundary-tiebreak.ts`, job role `tiebreak`): the two cuts as A and B in an order hashed from the run, the boundary and the attempt, each with its option strip (when listed) and a dense strip rendered at its time, no reasoning from either side; the skeptic's time applies only when the tie-break picks it (`tiebreak_skeptic`), the reviewer's is kept with a note when it picks that (`tiebreak_reviewer`), and `neither` faults the boundary for a person (`tiebreak_neither`). A skeptic fault that cites no image and tile time (`fault_image`, `fault_tile_t`), or cites a tile the image does not have, is recorded and ignored (`uncited`); a cited fault with no fix stays `apply_vision.py`'s rule 2 (`fault_no_fix`). `apply_vision.py` is untouched: the file Studio writes already carries the guarded decision, and every verdict also records the images the skeptic saw (`verdict.evidence`).
- **Prompts** (`BOUNDARY_RULE_VERSION` `by-eye-v2`, so every idempotency key is new): rules 7 (the source's own card marks the original break; cut on the first frame after it, never open an episode on it) and 8 (a burned-in caption on both sides of the cut is a split line) after the Workflow's six; a READING block (the cut is tile 6, the last of the first row; tiles 1-5 are this episode and tile 6 on the next; `motion` is a detector reading that fires on flares, cards and camera moves, never the time of an impact; the dialogue list is no evidence of the picture); the option facts say `motion detector: moving at the cut` / `still at the cut (motion Xs before, Ys after)` and no longer repeat the lines; the boundary facts state the planner's neighbours and the range this cut must lie in, and an option outside it, or inside a card span (`ON THE CARD`, with the first frame after the card named), is marked and refused by the check — for the reviewer's pick, the skeptic's fix and, as a mark, a tie-break side; the film notes go in whenever the run has them. The reviewer records `options_seen` (per option: what its own image shows before and after the cut, a caption across the cut, a card or flare and where, a physical action across the cut) BEFORE `chosen_key`; the skeptic records `chosen_strip_shows` before its verdict, must cite `fault_image` and `fault_tile_t` for a fault, is offered only the legal cuts its images show (`legalCutsInView`) and is told a fix must be a time it has looked at inside the range.
- **Evidence.** The runner renders the skeptic's dense strip by default (as before) and, new, an **annotated copy** of every strip the model sees (`annotateStrip`: ffmpeg `pad` + `drawtext` + `drawbox` over the pipeline's PNG into `<work>/annotated/`: a header naming the option and the cut time, the time on every tile, END on the tiles before the cut and NEXT from the cut tile, a red frame on the cut tile; the geometry read from the PNG's own size against `boundary_frames.py`'s `margin=4:padding=4`). `verdict.evidence[].annotated` and the job input say which was sent; `SEGMENT_STRIP_ANNOTATE=off` sends the raw PNGs; `STUDIO_ANNOTATE_FONT` names the font (Windows' Arial by default). The Workflow's `RULES` are not mirrored: that repo is read-only from Studio.
- **The eval** (`scripts/segment-eval.ts`) scores against the newest `review/cuts-*-DELIVERED.json` (`deliveredTruth`: each options boundary's delivered end inside its own half-window; `--truth records` keeps the old measure), always with dense strips, annotated strips and film notes (`SEGMENT_FILM_NOTES`, else the film's STATE.md "Film-specific notes"; a film with neither refuses), reads `.env.local`, takes `--boundaries 1-20` (index ranges, `#n`, or times) and `--model`, and prints the applied agreement with and without the skeptic, the skeptic's effect (agreed, disputed, fixes named, applied, rejected per rule, uncited, tie-break outcomes, helped, hurt, bad overrides), the DP-pick rate, the card boundaries, the three hard-rule checks (`scoreAgainstTruth`: an applied cut inside a card span, an episode out of band with the applied neighbours, an applied override no image covered) and the calibration bar (`lib/segment/calibration.ts`). Tests: `tests/segment-guard.test.ts` (the guard's four refusals, each outcome through `judgeBoundaries` and `reviewState`, the annotation filter and copy with a fake ffmpeg, the scoring and the CLI's pure parts), `tests/segment-vision.test.ts` (the prompt snapshots, the tie-break call in the pass).
- **The first calibration under the new rules (2026-09-23, `deepseek-flash`, no `ANTHROPIC_API_KEY` yet, so no Claude arm).** Against the delivered cuts at ±0.2 s, dense and annotated strips, film notes from STATE.md, concurrency 3, about $0.45 and 95–110 s wall per 20 boundaries. The API pass stays a pre-screen a person reviews; the Claude arms (Sonnet 5, Opus 5) run the moment the key is in `.env.local` (`--model claude-sonnet-5`).

**Snapshots and Studio's own files.** Before every apply and every render, `cut/review/*` (without the frame strips and QA sheets) and `cut/cuts.json` are copied to `<STUDIO_WORK_DIR>/<run id>/snapshots/<label>-<stamp>/` (`projects/` is not in git). The run's log is `<work>/logs/run.log`; the skeptic's dense strips go to `<work>/dense/` and the annotated copies of every strip the model sees to `<work>/annotated/`; proxy clips (±5 s, 480 px, made by ffmpeg from the source on first request) to `<work>/proxies/t<s>_<ms>.mp4`; join clips (the last 2 s of episode k and the first 2 s of k+1 as `cut_episodes.py` encoded them, delogo included; ffmpeg `-sseof -2` on the first, `-t 2` on the second, the concat filter) to `<work>/joins/j<kk>_t<s>_<ms>.mp4`, cut from Studio's own hardlinks of the built files under `<work>/eps/epNN-<mtime>-<size>.mp4` (the pipeline's `eps/` path is never opened) and remade once a re-render makes either file newer; the QA report as it was before an `--only` run to `<work>/qa/`. Nothing of Studio's lands in `projects/` beyond what the pipeline itself writes.

**Refusals shown verbatim.** A script's exit 1 fails the stage with `refusalOf`: the block from the first `REFUSED` / `FAIL` / `NOT READY` line on stdout, else the `sys.exit("…")` text on stderr, prefixed `<script> exited <code>`. Examples the desk shows as written: `pick_cuts.py exited 1 / REFUSED: this film has delivered cuts (review/cuts-0-900-DELIVERED.json). Add --pin-from …`; `cut_episodes.py exited 1 / REFUSED - nothing rendered: / no index/watermark.json - run watermark.py --detect, or pass --no-delogo …`; `boundary_frames.py exited 1 / NOT READY - 3 fault(s) across 12 options: …`; the sync's `drama-remix has uncommitted changes (…): commit them, or allow a dirty tree in the run's settings`. Studio never retries with `--force`, `--no-pin`, `--allow-recut` or `--no-delogo` on its own; `{kind: "retry"}` sends a failed run back to the stage that failed, unchanged.

**Cancel** (`POST …/cancel`) writes `cancelled` at once (the CAS ignores the lease); a worker mid-script sees it at its next heartbeat, kills the child and releases the heavy lock and the run lock. The route removes the run lock itself only when no live lease holds the run (a waiting run, or a dead worker's expired lease): while the worker's children may still be writing, `cut/.studio-run.json` stays, so a session reading the README's rule does not start `pick_cuts` or `cut_episodes` over them. The film folder is left as it is; a run cancelled at its review is not resumed (retry is for a failed run) — a new run on the same slug takes the folder over with fresh options.

**Routes** (staff; the create, decide and cancel routes admin only; same-origin guard, zod, JSON): `GET /api/admin/films/sources?dir=<downloads|onedrive|workspace|extraN|fake|absolute path>&probe=1` (the picker: Downloads, OneDrive "Mini Drama", the workspace, `STUDIO_SOURCE_ROOTS` folders; a typed path must be inside one), `POST /api/admin/films/runs` (one live run per film folder; an existing film folder is refused here by the intake's rule, 409 in its words, before a row exists), `GET /api/admin/films/runs[?producer_id]`, `GET /api/admin/films/runs/[runId]` → `{run, stage_view}` (`lib/segment/view.ts`; `lib/segment/api-types.ts` re-exports the types), `POST …/decide`, `POST …/cancel`, `GET /api/film-runs/[runId]/evidence/<review|index|work>/<path>.<png|json|mp4>` (Range honoured; `work/proxies/…` and `work/joins/…` are made on first request; nothing else is served: never an episode, never the source).

**Environment:** `WORKSPACE_ROOT`, `STUDIO_WORK_DIR`, `DRAMA_REMIX_ROOT`, `STUDIO_PIPELINE_PYTHON`, `HEAVY_LOCK_ROOT`, `STUDIO_BASH` (as `.env.example` documents them), plus `STUDIO_FAKE_PIPELINE=1` (the fake), `STUDIO_SOURCE_ROOTS` (extra picker folders, `;`-separated on Windows), `STUDIO_SEGMENT_WORKER=off` (no in-process worker), `STUDIO_FAKE_FIXTURE_FILM` (the film the fake derives from), `SEGMENT_STRIP_ANNOTATE=off` (the raw strips instead of the annotated copies), `STUDIO_ANNOTATE_FONT` (the annotation font file), `SEGMENT_FILM_NOTES` (the eval's film notes). Tests: `tests/segment-stages.test.ts` (the pure pieces), `tests/segment-worker.test.ts` (the whole run over the fake with its join clips, cancel, a cancel that leaves the lock to a live lease, a landscape refusal, a band-breaking move, a join with the QA merge, a re-judge the person closes, the hand-off, an Import now pressed before READY, a resume, a first proof extended under its pins, a film delivered to its end, a run cancelled at its review taken over by a new run, a delivered film and a session's folder refused without the explicit settings — at create time and by the worker without a lock file), `tests/segment-vision.test.ts` (the API pass and the band fix, a cancel between calls included).

## Screens

Staff only (decision 2026-09-23 #9); the sidebar entry "Segment a film" sits beside "Import films". Every screen reads through the staff routes; `lib/segment/api-types.ts` is the one module that holds the wire contract — zod for the request bodies, kept in step with the routes' own parsers, and type re-exports of the served replies (`StageView`, `BoundaryView`, `SourceListing`, `QaReport`, `FilmMetaForm`), so the screens render exactly what `lib/segment/view.ts` builds. Every image or clip URL comes ready-made in the stage view (`strip_url`, `proxy_url`, `image_urls`, `sheets[].url`); a screen never composes an evidence path. Strings live under `seg.*` in `locales/_keys/segment.json`; the classes are in `app/segment.css` (prefix `sgm-`, tokens only; `.seg` is the segmented control and is not ours).

**What the screens derive and what they never do.** `components/admin/segment/model.ts` is the pure model the tests cover (`tests/segment-screens.test.ts`): `buildCards` reads the served `BoundaryView` (status, reasons, applied time, current time) into cards; `episodesOf` / `neighbours` / `checkMove` / `bandConflictGroups` / `applyReady` are the length arithmetic, the same rule the decide route runs (`moveRefusal`), so a refusal is seen before it is sent; `orderCards` is the B3 order; `progressText` puts the worker's `stage_detail` into words. The screens never hand-edit `choices.json`, never compose a pipeline command themselves (the hand-off call comes from the worker), and never retry a refusal on their own: a failed run shows the pipeline's words and Retry goes back to the stage that failed with nothing added.
